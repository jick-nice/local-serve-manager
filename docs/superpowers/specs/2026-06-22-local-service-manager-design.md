# 本地服务管理软件设计文档

日期：2026-06-22

## 目标

构建一个 Windows 桌面软件，用来管理本机大量开发项目的前端、后端和自定义服务。软件支持选择项目根目录自动扫描，也支持手动添加服务；能识别常见技术栈、推荐启动命令、配置端口和备注；能一键启动、停止服务，并在内嵌日志抽屉里查看实时日志。

软件第一版使用 Electron + React + SQLite + electron-builder。所有项目文件放在当前工作目录 `E:\Work\ServeManager` 下。交付物为 Windows 安装包，安装后创建桌面快捷方式。

## 范围

第一版包含：

- Windows 桌面应用，不做 macOS 或 Linux 适配。
- 项目分组列表，一个项目下可以包含前端、后端、自定义等多个服务。
- 自动扫描项目根目录，生成服务草稿。
- 手动添加服务文件夹。
- 自动识别 Flutter、Vue、React、Flask、FastAPI、uvicorn、Spring Boot、Maven、Gradle。
- 识别不到的技术栈支持手动填写启动命令。
- 每个服务支持服务名、目录、技术栈、启动命令、端口、备注。
- 启动前检测端口冲突，并推荐可用端口，由用户确认替换。
- 启动前检测常见依赖缺失，弹窗询问是否安装。
- 启动、停止本软件创建的服务进程树。
- 内嵌日志抽屉显示 stdout 和 stderr。
- SQLite 保留项目和服务配置。
- SQLite 中的运行日志只保留本次会话，退出软件时清理日志表。
- 退出软件时如有运行中服务，弹窗询问是否停止后退出。
- 使用 electron-builder 打 Windows 安装包。

第一版不包含：

- 不做远程服务器管理。
- 不做系统服务注册。
- 不接管本软件之外启动的进程。
- 不提供一键结束端口占用进程。
- 不自动删除或修改用户项目目录文件。
- 不默认自动安装依赖，必须用户确认。
- 不做账号、多用户、云同步。

## 架构

应用分三层：

1. Electron Main

   负责本机能力，包括选择文件夹、扫描项目、识别技术栈、检测端口、启动进程、停止进程树、收集日志、读写 SQLite、退出前确认。

2. React Renderer

   负责界面，包括项目分组列表、服务行、端口和命令编辑、备注编辑、运行状态、启动和停止按钮、日志抽屉、依赖安装确认弹窗。

3. SQLite 本地存储

   长期保存项目配置和服务配置。临时保存运行日志，退出时清空日志表。

Renderer 不能直接执行系统命令。所有本机操作通过 Electron preload 暴露的受控 IPC API 调用 Main 层。

## 界面设计

主窗口采用本地工具型布局，紧凑、可扫描、列表优先。

顶部工具栏包含：

- 添加项目
- 手动添加服务
- 搜索框
- 状态筛选
- 停止全部

中间主体是项目分组列表：

- 项目组标题显示项目名、根目录、运行中服务数量。
- 组内每个服务一行。
- 服务行显示服务名、技术栈、目录、端口、启动命令、备注、状态和操作按钮。
- 操作按钮包括启动、停止、日志、编辑、删除。
- 服务运行中时禁止修改目录和启动命令，只允许停止和查看日志。

日志抽屉位于右侧或底部：

- 点击服务行的日志按钮打开。
- 实时显示该服务本次运行的 stdout 和 stderr。
- 支持自动滚动、清空当前显示、复制日志。
- 日志清空只影响软件内日志，不影响服务自身生成的文件日志。

## 项目添加流程

自动扫描流程：

1. 用户点击添加项目。
2. 选择项目根目录。
3. Main 层扫描根目录和常见子目录。
4. 识别到服务后生成草稿。
5. 用户确认或修改服务名、端口、命令、备注。
6. 保存项目和服务配置。

手动添加流程：

1. 用户点击手动添加服务。
2. 选择服务目录。
3. Main 层执行一次技术栈识别。
4. 识别成功则填入建议命令。
5. 识别失败则要求用户填写启动命令。
6. 用户选择所属项目分组或新建项目分组。
7. 保存服务配置。

自动扫描会优先检查这些目录名：

- `frontend`
- `web`
- `client`
- `admin`
- `backend`
- `server`
- `api`
- 根目录本身

## 技术栈识别

Vue 和 React：

- 识别文件：`package.json`
- 识别依赖：`vue`、`react`、`vite`、`next`
- 命令优先级：`dev`、`start`、`serve`
- 包管理器识别优先级：`pnpm-lock.yaml`、`yarn.lock`、`bun.lockb`、`package-lock.json`
- 推荐命令示例：`pnpm dev`、`npm run dev`、`yarn dev`、`bun run dev`

Flutter：

- 识别文件：`pubspec.yaml`
- 默认推荐命令：`flutter run -d windows`
- 如果用户要运行 Web，可手动改为 `flutter run -d chrome --web-port <port>`

Flask：

- 识别文件：`requirements.txt`、`pyproject.toml`、`app.py`
- 识别依赖或导入：`flask`
- 默认推荐命令：`flask --app app run --port <port>`

FastAPI 和 uvicorn：

- 识别文件：`requirements.txt`、`pyproject.toml`、`main.py`
- 识别依赖或导入：`fastapi`、`uvicorn`
- 默认推荐命令：`uvicorn main:app --reload --port <port>`

Spring Boot / Maven：

- 识别文件：`pom.xml`
- 默认推荐命令：`mvn spring-boot:run`

Spring Boot / Gradle：

- 识别文件：`build.gradle`、`build.gradle.kts`
- 有 wrapper 时默认推荐命令：`gradlew bootRun`
- 没有 wrapper 时默认推荐命令：`gradle bootRun`

识别结果只是草稿。用户可以在保存前修改命令、端口和备注。

## 端口策略

每个服务可以配置端口。启动前 Main 层检测端口是否占用。

如果端口空闲：

- 直接启动服务。

如果端口被占用：

- 显示冲突提示。
- 推荐相邻可用端口。
- 用户确认后替换服务端口并启动。
- 用户取消则不启动。

软件不提供一键结束占用端口进程，避免误杀其他开发工具或系统服务。

## 依赖提示

软件只在启动前做轻量依赖检测，不默认安装依赖。

Node：

- 检测 `node_modules` 是否存在。
- 缺失时提示安装。
- 推荐安装命令按包管理器生成，例如 `pnpm install` 或 `npm install`。

Python：

- 检测 `.venv` 是否存在。
- 检测 `requirements.txt` 或 `pyproject.toml` 是否存在。
- 缺少虚拟环境或依赖安装痕迹时提示用户。
- 推荐命令可使用项目目录下的 Python 环境约定，用户确认后执行。

Java：

- 检测 Maven 或 Gradle wrapper。
- 缺 wrapper 时仍允许使用本机 `mvn` 或 `gradle`。
- 依赖下载由 Maven 或 Gradle 启动过程处理，软件只提示可能需要等待。

依赖安装弹窗必须显示执行目录和命令。用户确认后才执行。

## 进程管理

服务启动：

- 使用 `child_process.spawn` 在服务目录中启动。
- 保存进程 ID 和进程树信息。
- 收集 stdout 和 stderr。
- 更新服务状态为运行中。

服务停止：

- 只停止本软件启动的服务。
- 停止整个进程树，避免子进程残留。
- 更新服务状态为已停止。

退出软件：

- 如果没有运行中服务，直接退出并清理日志表。
- 如果有运行中服务，显示确认弹窗。
- 用户选择停止后退出，则停止所有由软件启动的服务，清理日志表，再退出。
- 用户取消退出，则继续运行软件。

## 安全边界

- 只执行用户确认过的启动命令或安装命令。
- 自动识别生成的命令必须作为草稿展示给用户。
- 命令默认在服务目录执行。
- 不删除用户项目目录内的任何文件。
- 删除服务只删除软件配置和日志。
- 停止服务只处理本软件启动的进程树。
- 不提供杀端口进程功能。
- Renderer 不直接执行命令，只通过受控 IPC 调用 Main。
- IPC API 按功能拆分，不暴露任意命令执行入口给界面。
- 路径、备注、命令输入需要保存为数据，不作为 HTML 直接注入。

## 错误处理

- 目录不存在：服务标记为路径失效，禁止启动，提示用户重新选择目录。
- 命令为空：禁止启动，提示用户填写启动命令。
- 命令启动失败：状态改为失败，错误写入日志。
- 端口检测失败：提示用户，允许取消启动。
- SQLite 写入失败：提示保存失败，不更新界面为成功状态。
- 停止进程失败：提示用户，并保留运行状态供再次停止。
- 依赖安装失败：错误进入日志，服务不自动继续启动。
